# Experiment corpus and parameter ledger

## Issue Target And Scope Summary

- Issue target: #44
- Title: Experiment corpus and parameter ledger for fitting loops
- Source context: GitHub issue #44, `00-context.md`, `docs/diagnostics/snapshot-and-allocation.md`, `docs/diagnostics/runtime-validation-history.md`, `docs/planning/mvp-roadmap.md`, and the existing parser/fitting tooling.
- Scope: add a lightweight repo-local corpus format, parameter ledger convention, synthetic fixtures, and a file-based summary workflow for future shadow replay and controlled-live fitting loops.

## Strategy

- Keep #44 as infrastructure only. Do not change allocator scoring, command application scope, vanilla salvo suppression, projectile physics, missile guidance, or live combat behavior.
- Document a durable registry entry schema that preserves experiment identity, run mode, scenario tags, artifact links, heuristic candidate identity, parameter snapshot hash, and manual verdict.
- Keep evidence modes separated in every summary. Shadow replay remains a candidate filter and regression check; controlled live remains the causal combat-behavior evidence source.
- Use committed synthetic fixtures under `tools/fixtures/experiment_corpus/` for validation. Keep generated and private experiment artifacts under ignored `artifacts/` paths.
- Add a small standard-library Python summarizer that reads registry JSONL, validates required fields, checks artifact links, reads optional fitting `summary.json` artifacts, and writes corpus-level JSON/CSV/Markdown outputs.

- `docs/diagnostics/experiment-corpus.md` is the durable user-facing schema and workflow source of truth.
- `tools/summarize_experiment_corpus.py` is the first implementation of corpus aggregation.
- `tools/fixtures/experiment_corpus/` contains synthetic fixture-only registry and artifact examples.
- `artifacts/experiments/**` and `artifacts/fitting/**` remain local/generated by default and are not committed.

## Known Risks And Assumptions

- The first corpus tool summarizes existing evidence fields; it does not infer exact kill attribution or causal effectiveness from shadow replay.
- Private raw logs may be intentionally absent from committed fixtures and local registry entries.
- Parameter snapshots are immutable run provenance. Updating allocator defaults later requires a new parameter snapshot, not retroactive reinterpretation.
